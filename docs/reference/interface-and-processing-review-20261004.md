# 界面与处理流程核对（2026-10-04）

范围：公开仓库 3.1.7 基线、用户提供的八张截图、生产组件和此前提供的已脱敏 SMART 日志。此次界面修改保留主题 ID、任务模型、快捷键行为、凭据和下载参数语义。

## 界面处理

使用 Impeccable 的 distill 与 craft-floor、UI UX Pro Max 的桌面工具风格检索、Emil Design Engineering 的控件与交互检查。

| Before | After | Why |
| --- | --- | --- |
| 列表常驻 J/K/Space 提示；搜索和解析按钮重复显示快捷键 | 删除常驻提示和重复文案，保留键盘事件处理 | 核心操作不需要被说明文字包围 |
| 主题图标和名称整体居中，名称本身偏右；菜单选中标记改变重心 | 等宽首尾图标列，名称独立占中列 | 以控件几何中心验收，而不只检查 text-align |
| 石墨只有黑色顶栏，工作表面浅灰，菜单状态出现浅底白字 | 深色 Canvas / Surface / Subtle，雾蓝强调，显式顶栏按钮色对 | 表面层次和文字对比度一致 |
| 完成状态和打开文件夹都使用绿色 | 完成状态保留 Success，打开文件夹使用 Primary | 状态色与可点击主动作分开 |
| 视频尺寸只有小图标和灰字 | 视频文字、尺寸与 Selected 底色成组 | 视频信息更容易扫描，检测值不冒充最终文件属性 |
| 开关已选滑块直接使用正文色 | 使用 on-primary | 选中和未选中状态都能清楚辨认 |

## 风格依据

[Radix Colors](https://www.radix-ui.com/colors/docs/palette-composition/composing-a-palette) 提供灰阶与强调色的角色划分；[Radix Themes](https://www.radix-ui.com/themes/docs/theme/color) 提供成套明暗颜色尺度。此次借鉴其中性灰层次，并为本产品单独验对比度，没有引入组件依赖或复制整套主题代码。

[Nord](https://www.nordtheme.com/) 的 Polar Night / Snow Storm 提供冷静、低饱和的主题方向。适合桌面媒体工具，但其原始强调色不应直接套给所有状态。此次石墨使用更中性的炭灰与雾蓝；蓝宝石、酒红保留各自身份，避免紫色、孔雀青和朱橙。

这些是成熟的参考体系；未取得对“广受好评”的独立统计，不以流行度代替当前界面的实际验收。

## 日志流程与提速机会

源码调用链：`DownloadService::get_metadata` → SMART 六客户端顺序探测 → `get_metadata_internal` → 公共参数构建 → yt-dlp JSON / JS challenge / PO Token → 能力清单与 winner → 下载时继续使用 winner → 下载及后处理。见 `src-tauri/src/services/download.rs`。

原日志中可直接计数：6 次客户端尝试，7 次 SponsorBlock 请求（6 次解析、1 次下载），4 次 Bun 兼容警告。未提供各阶段可靠时间戳，不能据此声明慢了多少秒或承诺百分比提升。

| 机会 | 依据 | 处置与验收 |
| --- | --- | --- |
| 解析阶段不请求 SponsorBlock | 公共参数把 `--sponsorblock-remove all` 带入每次 `--dump-json`；日志重复请求六次 | 优先候选。应分离解析参数与下载后处理，保留下载时 SponsorBlock；比较能力清单、winner、分辨率、片段裁剪和文件名，确认无行为损失 |
| 减少其他解析阶段后处理参数 | 解析公共参数携带嵌入字幕、元数据、封面等下载选项 | 先分别确认哪些选项实际增加工作；不能把所有参数都视为已测量瓶颈 |
| 检查 EJS 运行时兼容性 | 日志 Bun 1.4.2 超出该 EJS 支持范围；[yt-dlp 公告](https://github.com/yt-dlp/yt-dlp/issues/16766) 将 Bun 支持限定为 1.2.11–1.3.14，并宣布弃用 | 与性能分开处理。开发包管理器和产品 JS 解题运行时是不同执行面；未在此次 UI 修改中替换工具或假定警告就是失败原因 |
| 减少重复网页与 token 获取 | 每个独立 yt-dlp 进程重复提取网页、客户端 API 和部分 JS / POT 工作 | 会话缓存可研究，但必须绑定 URL、身份、参数、有效期和工具版本，避免复用过期授权；尚未实现 |
| 按目标分辨率提前停止 | 现有 SMART 扫描六客户端后选最大检测能力 | 不直接采纳：best 模式提前结束可能丢失高画质，且改变完整能力清单；并发探测也不能绕过匿名重试及顺序契约 |
| 调大并发片段数 | 当前默认 `-N 4` | 仅适用于分片流；不能推断普通 HTTP 下载会更快。不改默认值，先按真实媒体协议与错误率测量 |

此次交付的是有证据的提速调查，未修改下载后端、取消流程、认证策略或网络并发。进一步实施应先建立原生对照样本和阶段耗时记录。

## 验证边界

自动化验证包括组件契约、全量前端测试、三主题双语任务与设置矩阵，以及空/活动工作区的尺寸、文字居中和对比度检查。浏览器结果证明 WebView 排版与交互结构，不证明真实 YouTube 下载、Windows 原生 DPI 或人工验收。最终记录以本次 `.scratch/interface-*` 日志及矩阵结果为准。
