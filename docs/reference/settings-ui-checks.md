# 设置页界面检查

## 执行与计数

- `bun run test:ui-settings`：执行一次完整检查，生成一张截图。
- `bun run test:ui-settings -- --capture-themes`：执行同一套检查一次，再切换三个主题生成三张截图。
- 布局覆盖为正式主题 × 中英文 × 360 / 720 / 960 像素容器宽度；当前为 18 种组合，每种组合检查四个设置标签。
- 与主题、宽度无关的工具更新及健康检查行为，按中英文各执行一次。
- `caseCount` 表示布局组合数；`behaviorCaseCount` 表示行为验证的语言组合数；`scenarios` 列出场景；`checkCount` / `passedChecks` 表示断言次数；`screenshotCount` 单独计数。截图不增加组合数或断言数。
- `durationMs` 覆盖检查、截图和最终进程清理。进程启动和报告写入的额外开销可通过外部命令计时测量。

检查失败返回非零退出码。截图准备、捕获或写入失败也须报错，包含对应截图名；不能用已有截图或检查成功替代截图成功。

每次运行先原子写入带 `runId` 的 `RUNNING` 报告；流程结束后写入 `PASS` 或 `FAIL`。异常也写入本次失败报告。中断时保留 `RUNNING`，不会将上一轮的成功报告当作本轮结果。

`bun run typecheck:ui` 检查 `tests/ui` 的类型，并在 CI 执行。此检查使用浏览器支持的 ES2022 标准库；生产源码的编译目标保持原有配置。

## 保留和退役原则

- 保留所有布局组合中的溢出、文本截断、键盘导航、操作尺寸和选中导航对比度检查。
- 主题无关的重复行为集中验证；保留健康检查忙碌/失败、清理互斥、更新成功/失败恢复及重试。
- 每个主题单独验证批准的主色、表面色及语义对比度。设计契约和可访问性检查承担不同职责，不能相互替代。
- 分组标题与正文颜色 token 比较，不复制各主题的正文 RGB。
- 删除旧文案和旧类名的检查前，核对当前产品、设计规则及其他检查。当前透明分组、同表面工具行和无应用内自更新等有效约束继续保留。
